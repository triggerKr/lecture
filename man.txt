requireWithFriendlyErrorv  함수에서 node_modules/rollup/dist/native.js:121 에서 throws new Error(
 이렇게 에러났고 Error Cannot find module @rollup/rollup-linux-x64-gnu. npm has a big related to optional dependencies (https://github.com/npm/cli/issues/4828). please try 'npm i' again after removing both package-lock.json and node_modules 이런 에러스택도 나왔어

태원님, 이 에러는 Jenkins 자체의 문제가 아니라 npm이 Rollup의 optional dependency를 제대로 설치하지 못해서 발생하는 매우 흔한 문제입니다. 특히 Linux 서버에서 npm install을 수행할 때 종종 발생합니다.

에러의 핵심은 이것입니다.

Error: Cannot find module '@rollup/rollup-linux-x64-gnu'

npm has a bug related to optional dependencies
https://github.com/npm/cli/issues/4828
Please try 'npm i' again after removing both package-lock.json and node_modules

여기서 중요한 부분은

Cannot find module '@rollup/rollup-linux-x64-gnu'

입니다.

Rollup은 실행 중에 OS에 맞는 Native Binary를 찾습니다.

Linux라면

@rollup/rollup-linux-x64-gnu

패키지가 설치되어 있어야 하는데 설치되지 않았다는 뜻입니다.

왜 이런 현상이 발생하는가?

Rollup은 package.json에서

optionalDependencies

를 사용합니다.

예를 들면

Windows
  @rollup/rollup-win32-x64-msvc

Linux
  @rollup/rollup-linux-x64-gnu

Mac
  @rollup/rollup-darwin-arm64

이런 식으로 운영체제마다 다른 패키지를 설치합니다.

그런데 npm의 오래된 버그 때문에

optionalDependencies

↓

설치 안됨

↓

rollup 실행

↓

module not found

이 발생합니다.

Jenkins에서 가장 많이 발생하는 원인
1. node_modules를 재사용

Jenkins Workspace에

node_modules

가 남아 있습니다.

예를 들어

윈도우에서 설치

↓

Linux Jenkins에서 그대로 사용

↓

linux binary 없음

이런 경우가 많습니다.

2. package-lock.json 문제

package-lock.json에

Windows용

@rollup/rollup-win32...

정보가 들어있는데

Linux에서 그대로 사용하면

Linux Binary를 설치하지 않는 경우가 있습니다.

3. npm 버전 버그

npm

8.x
9.x

에서 많이 발생했습니다.

npm 10에서는 상당 부분 수정되었습니다.

해결 방법 (추천 순서)
방법 1 (가장 권장)

빌드 전에 깨끗하게 삭제

rm -rf node_modules
rm -f package-lock.json

npm install

그 후

npm run build
방법 2

npm cache까지 삭제

npm cache clean --force

rm -rf node_modules
rm package-lock.json

npm install
방법 3

Jenkins에서 항상 Fresh Install

현재

npm install

대신

npm ci

를 사용하는 경우라면,

package-lock.json이 잘못 생성되어 있으면 같은 문제가 반복될 수 있습니다.

이 경우

node_modules 삭제

package-lock 삭제

새로운 package-lock 생성

npm install

을 한 번 수행한 후 Jenkins에서 사용합니다.

방법 4

Rollup 직접 설치

임시 해결 방법입니다.

npm install @rollup/rollup-linux-x64-gnu --save-dev

하지만 이 방법은 근본 해결책은 아닙니다.

Jenkins Pipeline이라면

빌드 전에 아래 과정을 넣는 것이 가장 안전합니다.

rm -rf node_modules
rm -f package-lock.json

npm install

npm run build
확인해야 할 사항

Jenkins 서버에서 아래 명령의 결과도 확인해 보시는 것이 좋습니다.

node -v
npm -v
uname -a
cat /etc/os-release

그리고 프로젝트의

cat package.json

내용도 함께 확인하면 Rollup과 Vite 버전 간의 호환성 문제 여부도 판단할 수 있습니다.

제가 가장 의심하는 원인

태원님 상황을 보면 P-DEP의 Jenkins가 Linux 서버에서 빌드하고 있고, 이전에도 개발 환경과 운영 환경이 Windows와 Linux로 나뉘어 있다고 말씀하셨습니다. 이 경우 가장 가능성이 높은 원인은 다음 두 가지입니다.

Jenkins Workspace에 기존 node_modules가 남아 있음.
Windows에서 생성된 package-lock.json을 Linux Jenkins가 그대로 사용하면서 @rollup/rollup-linux-x64-gnu가 설치되지 않음.

이 두 가지가 실제 현장에서 가장 흔한 원인입니다.
